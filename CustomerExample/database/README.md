# Banana Commerce Oracle Sample Database

This folder contains an executable, fictional Oracle source workload for migration assessment. It is deliberately more involved than a basic sample schema and models the PeelPay Commerce application described in the Banana Inc evidence pack.

Do not use this schema or data in production. All people, businesses, contact details, payment references and transactions are fictional.

## Included complexity

- Twelve related transactional, reference, audit and integration tables.
- Monthly interval partitioning and local indexes on the order table.
- Composite keys, foreign keys, unique constraints and JSON validation constraints.
- Sequences and row triggers for identifiers, totals, timestamps and auditing.
- A PL/SQL package implementing order creation, pricing, inventory reservation, payment, shipping and cancellation state transitions.
- Row locking and conditional inventory updates to prevent over-reservation.
- JSON outbox events representing integration messages.
- Operational, inventory-risk and daily-sales views.
- Deterministic fictional data: 5 customers, 8 products, 3 warehouses, 24 stock positions and 120 orders.

These constructs create useful migration questions around PL/SQL conversion, interval partitioning, JSON handling, trigger behavior, pessimistic locking, package APIs, event integration and target indexing.

## Prerequisites

- Oracle 19c or 21c. The repository database lab uses Oracle XE 21c.
- A disposable schema with these privileges: `CREATE SESSION`, `CREATE TABLE`, `CREATE VIEW`, `CREATE SEQUENCE`, `CREATE PROCEDURE`, and `CREATE TRIGGER`.
- Sufficient quota on the schema's default tablespace.
- SQL*Plus available on the machine where setup is run.

The existing lab bootstrap creates a suitable `migration_lab` user. The scripts do not create users, tablespaces, network links, queues or security policies because those require elevated administration privileges.

## Install

Run SQL*Plus from this directory. Omitting the password from the command line allows SQL*Plus to prompt for it:

```powershell
Set-Location CustomerExample/database
sqlplus migration_lab@//10.40.1.20:1521/XEPDB1 '@install.sql'
```

`install.sql` first removes only objects whose names begin with `BANANA_`, then creates, loads and validates the sample. It exits nonzero on any SQL or validation error.

To grant the repository lab's read-only user access after a successful installation:

```powershell
sqlplus migration_lab@//10.40.1.20:1521/XEPDB1 '@05-assessment-grants.sql'
```

That optional script expects `assessment_reader` to exist.

## Validate or remove

Rerun validation without rebuilding:

```powershell
sqlplus migration_lab@//10.40.1.20:1521/XEPDB1 '@04-validation.sql'
```

Remove all sample objects:

```powershell
sqlplus migration_lab@//10.40.1.20:1521/XEPDB1 '@00-uninstall.sql'
```

## Script order

| Script | Purpose |
| --- | --- |
| `00-uninstall.sql` | Idempotently removes `BANANA_%` objects from the current schema. |
| `01-schema.sql` | Creates sequences, tables, constraints, partitioning and indexes. |
| `02-business-logic.sql` | Creates triggers, the commerce package and reporting views. |
| `03-seed-data.sql` | Loads deterministic fictional master and transaction data. |
| `04-validation.sql` | Checks counts, integrity, compilation and object validity. |
| `05-assessment-grants.sql` | Optionally grants a pre-existing assessment user read access. |
| `install.sql` | Runs uninstall, creation, loading and validation in order. |

## Important limitations

- The sample represents one physical Oracle schema, not all seven fictional inventory databases.
- Enterprise-only topology such as RAC and Data Guard is documented but not emulated by the schema.
- Oracle AQ, VPD, database links and scheduler jobs are represented by migration concerns rather than created because they require broader privileges and environment configuration.
- Seed generation is deterministic in structure and count; timestamps generated by triggers reflect installation time.
