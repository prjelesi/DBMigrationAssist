DBMigrationAssist

Database Migration Assessment Portal & Automated Assessment Agent Platform

Version: 1.0 Date: 2026-07-24 Status: Planning Repo: prjelesi/DBMigrationAssist

Executive Summary

DBMigrationAssist is an end-to-end database migration assessment platform that enables cloud adoption teams and customers to systematically evaluate on-premises, Azure, and multi-cloud databases and generate AI-powered migration plans. The platform combines an assessment portal, distributed assessment agents running in Docker containers, an interactive questionnaire workflow, and an AI report generation engine to produce actionable, evidence-backed migration roadmaps.

Goals & Scope

In Scope

  • Web portal for assessment lifecycle management (environments, databases, agents, reports)
  • Questionnaire engine for collecting context not available from technical assessment alone
  • Distributed Docker-based assessment agents that connect to databases and submit results
  • Manual report upload for customers who cannot deploy agents (air-gapped environments)
  • Secure agent-to-backend communication using TLS + pre-shared key (PSK) authentication
  • AI-powered migration plan generation (Azure OpenAI / GitHub Copilot hosted)
  • Support for on-premises, Azure, and other cloud environments
  • Downloadable/shareable migration reports in PDF and JSON formats
  • Demo environment deployment via Azure Bicep (existing demo/ folder)

Out of Scope (v1)

  • Automated migration execution (assess only, not migrate)
  • Real-time database monitoring or ongoing drift detection
  • Schema conversion tooling (out of scope; recommend DMS, SSMA, ora2pg)
  • Multi-tenant SaaS billing and provisioning

Component Descriptions

1. Assessment Portal (Frontend)

Single-page application providing the management interface for the entire assessment lifecycle.

Pages / Views

PagePurpose
/dashboardOverview: active assessments, pending reports, agent status KPIs
/environmentsManage source environments (OnPrem, Azure, AWS, GCP)
/databasesDatabase inventory — add, edit, group databases by host/type
/agentsRegister agents, view status, download agent Docker image config
/assessmentsCreate assessments, link to databases, track progress
/assessments/:id/questionnaireMulti-step questionnaire wizard for an assessment
/reportsView, download, and share AI-generated migration reports
/uploadManual report upload for air-gapped environments
/settingsAI agent configuration, PSK management, system settings

Technology

React 18, TypeScript, Vite, TanStack Query, React Router v6, Tailwind CSS / shadcn-ui components

2. Backend API

FastAPI application serving both the portal and the assessment agents. All endpoints are versioned under /api/v1/. Portal endpoints use Azure Entra ID (OIDC) authentication; agent endpoints use PSK authentication via X-Agent-Key header.

Responsibility Areas

  • Inventory management — CRUD for environments, databases, agents
  • Agent configuration — serve agent config payload (connection strings, databases to assess, output format)
  • Assessment lifecycle — create, track, complete assessments
  • Report ingestion — receive and store agent-submitted reports and manual uploads
  • Questionnaire engine — serve questionnaire definition, receive answers
  • AI orchestration — trigger AI engine with questionnaire + assessment data, store result

3. Assessment Agents

Lightweight Docker containers deployed by the customer at or near the database host. Agents can run in two modes:

ModeDescriptionUse Case
Multi-DB One container assesses multiple databases of any type on a given host/network segment Lab environments, demo, small estates
Single-DB One container per database engine type; isolated, smaller blast radius Production environments, strict network segmentation

Collector Support

Each agent ships with pluggable collectors for: sqlserver, postgresql, mysql, mariadb, mongodb, cassandra, oracle

Agent Lifecycle

  1. Deployed with BACKEND_URL and AGENT_KEY env vars
  2. Registers itself with backend (POST /api/v1/agents/register)
  3. Pulls assessment configuration (GET /api/v1/agents/{id}/config)
  4. Runs collectors against each configured database
  5. Submits collected report (POST /api/v1/assessments/{id}/report)
  6. Goes idle (polling or terminates based on config)

4. Questionnaire Engine

Captures context that cannot be discovered automatically — business constraints, team skills, downtime tolerance, compliance requirements. Answers are combined with the technical assessment data to provide the AI engine with full context.

Questionnaire Categories

  • Environment — Source environment type, network connectivity, firewall constraints
  • Business — Acceptable downtime window, RTO/RPO, business criticality
  • Technical — Stored procedures, triggers, linked servers, special features used
  • Team — DBA skill level, Azure experience, training availability
  • Compliance — Data residency, PII/GDPR, regulatory requirements
  • Migration target — Preferred Azure region, landing zone availability, cost constraints

Agent Design & Communication

Agent Startup Sequence

# Docker run command (customer deploys)
docker run -d \
  -e BACKEND_URL=https://api.dbmigrationassist.example.com \
  -e AGENT_KEY=psk-xxxxxxxxxxxxxxxxxxxxxxxx \
  -e AGENT_MODE=multi      # or: single \
  -e AGENT_NAME=prod-dc1   # human-readable label \
  dbmigrationassist/agent:latest

Communication Protocol

DirectionEndpointMethodAuthDescription
Agent → Backend /api/v1/agents/register POST PSK Register agent, receive agent ID
Agent → Backend /api/v1/agents/{id}/config GET PSK Pull list of databases + credentials to assess
Agent → Backend /api/v1/agents/{id}/heartbeat POST PSK Periodic status update (running, progress %)
Agent → Backend /api/v1/assessments/{id}/report POST PSK Submit completed assessment report (JSON)

Pre-Shared Key (PSK) Authentication

  • Each agent deployment receives a unique PSK generated by the portal
  • PSK is sent in every request as X-Agent-Key: <psk> header over TLS
  • Backend validates PSK using constant-time comparison against value stored in Azure Key Vault
  • PSK can be rotated from the portal; old key has a 24-hour grace period
  • All agent endpoints are on a separate router with PSK middleware; portal endpoints use Entra ID OIDC

Security Model

All agent-to-backend communication MUST use TLS 1.2+. PSKs are minimum 32 random bytes, base64-encoded. Credentials in agent config payloads reference Azure Key Vault URIs — plain-text credentials are only permitted in demo/dev mode.
ConcernControl
Portal authenticationAzure Entra ID OIDC, JWT bearer tokens, scoped to tenant
Agent authenticationPre-shared key (PSK) in X-Agent-Key header, constant-time comparison
Transport securityTLS 1.2+ enforced for all API endpoints; agents refuse non-HTTPS backend URLs
Credential storageDatabase credentials stored as Azure Key Vault references, never in DB plain-text
PSK storagePSK stored in Azure Key Vault; backend reads via managed identity
PSK rotationPortal UI generates new PSK; 24h grace overlap period; old PSK logged then revoked
Report data at restAzure Blob Storage with customer-managed key (CMK) option
DB assess-only credentialsAgents use read-only / assessment-only DB accounts; principle of least privilege
Input validationPydantic models on all API inputs; no dynamic SQL, parameterized queries only
Rate limitingPer-agent-key rate limiting on report submission endpoint

AI Report Engine

After assessment reports are ingested and questionnaire responses are collected, the user triggers AI report generation. The backend orchestrates a call to a registered AI agent (Azure OpenAI GPT-4o or GitHub Copilot hosted model) with a structured prompt composed from:

  • Technical assessment JSON (collected by agents or uploaded)
  • Questionnaire responses (business context, constraints)
  • Migration path catalog (migration-paths.json — available migration routes per engine/version)
  • Scoring matrix (scoring-matrix.json — complexity, risk, effort scoring rules)

Registered AI Agents

Multiple AI backends can be registered in the system and selected per assessment:

Agent TypeConfigurationNotes
Azure OpenAI Endpoint URL, API key (Key Vault ref), deployment name, model version GPT-4o recommended; supports Assistants API for structured output
GitHub Copilot (Foundry) Azure AI Foundry endpoint, deployment, managed identity or API key Copilot-hosted model via Azure AI Foundry; same API surface as AOAI

Report Generation Prompt Strategy

System: You are a database migration expert. Analyze the technical assessment 
and questionnaire data provided. Generate a structured migration plan including:
1. Recommended migration target and justification
2. Migration approach (online vs offline, tool recommendations)
3. Effort estimate (person-days) by phase
4. Risk register with mitigations
5. Pre-migration checklist
6. Post-migration validation steps

Constraints: Base recommendations only on provided data. Flag any gaps.
Output format: JSON matching the MigrationReport schema.

User: [assessment_json] + [questionnaire_responses] + [migration_paths_catalog]
